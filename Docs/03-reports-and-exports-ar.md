# التقارير والملفات والأسماء — خزائن جاهز

هذا الملف يحدد عرض التقارير الخمسة وتنزيلاتها. اقرأ [مرجع API](02-api-integration-ar.md) للترقيم والصلاحيات و[الشاشات](01-screens-and-workflows-ar.md) لمصدر كل مبلغ.

## 1. نموذج طلب التقرير

```http
GET /api/jahez/v3/treasury/reports/movements?fromDate=2026-10-01&toDate=2026-10-19&page=1&pageSize=50
```

الفلاتر المشتركة: `fromDate,toDate,subAccountId,sponsorId,purpose,page,pageSize`، ويضاف `handoverId` للمحضر. استخدم حساب ترحيل محدداً عند اختيار الحساب؛ اختيار حساب أب لا يتوسع تلقائياً إلى أبنائه.

الاستجابة المشتركة `TreasuryReport`:

| الحقل | المعنى |
|---|---|
| `reportType` | نوع التقرير |
| `filter` | الفلتر الفعلي المستخدم من الخادم؛ قد يثبت كفيل التجارية |
| `accounts` | أرصدة وحركة الحسابات للفترة، مع صفوف تجميعية |
| `movements` | تفاصيل القيود، مرقمة في JSON بحسب النوع |
| `fuel` | نتائج مطابقة بترو آب |
| `handover` | المحضر المجمد أوnull |
| `totalMovements` | عدد القيود المطابقة للفلتر، وليس عدد حسابات/شركات التقرير |

الأقسام غير المستخدمة قد تكون فارغة. لا تعرض جداول فارغة بلا معنى لكل نوع. `totalMovements` ليس مبلغاً ولا عدد إيصالات العملاء، لأن التحويل ينشئ طرفين والتصحيح يحتفظ بقيوده المتعددة.

## 2. تقرير حركة الخزائن — `movements`

العنوان «حركة الخزائن». يعرض `accounts` للمجاميع و`movements` للتفاصيل. في كل حساب: أول المدة، المقبوضات، المدفوعات، التحويل الوارد، التحويل الصادر، آخر المدة.

تفصيل الحركة: تاريخ ووقت الرياض، اسم الحساب، اسم الكفيل المثبت، نوع القيد، المبلغ الموقع، المرجع، اسم المندوب عند وجوده، الإقامة إن وجدت، واسم المنفذ. لا تعرض batchId أو أي GUID مكان اسم شخص أو مرجع مطبوع.

الحسابات المالية للفترة:

```text
آخر المدة = أول المدة + المقبوضات - المدفوعات + التحويل الوارد - التحويل الصادر
```

المقبوضات والمدفوعات في هذا العقد تشمل قيود الفترة غير المصنفة Transfer، بما فيها الافتتاح والتسوية والعكس حسب الإشارة. ليست «مبيعات» أو «إيراد رسوم» فقط. أول المدة يشمل ما سبق بداية الفترة؛ آخر المدة يشمل ما قبل نهاية اليوم الأخير.

تجزئة JSON للتفاصيل لا تغير المجاميع: `accounts` للفترة كاملة، و`movements` للصفحة المطلوبة فقط. لا تحسب المجاميع من الصفحة الحالية. مجموع كل التحويلات الداخلية عبر المصدر والوجهة لا يخلق مالاً جديداً، لكن ترشيح حساب واحد يظهر أثره على ذلك الموقع.

## 3. محضر التسليم — `handover`

```http
GET /api/jahez/v3/treasury/reports/handover?fromDate=2026-10-01&toDate=2026-10-19&handoverId=<selected-handover-id>
```

التقرير لمحضر **مؤكد** فقط. وجود تاريخين مطلوب لصحة العقد، لكن محتوى المحضر هو النسخة المجمدة المحددة بـhandoverId، وليس إعادة تجميع الحركة بتواريخ الفلتر. لا تستخدم تغيير فلتر الشركة أو الحساب لحذف سطور من محضر مؤكد؛ التقرير يرجع المحضر كاملاً.

اعرض:

- رقم المستند `documentNumber` واليوم المحاسبي.
- المشرف المسلم والمحاسب المستلم بأسمائهما المحفوظة، لا معرفاتهما.
- وقت التأكيد وسببه وحالة المحضر.
- النقدية المستلمة وحدها كإجمالي نقدي.
- البنك وبترو آب كبنود غير نقدية مستقلة.
- تفصيل الكفيل ورقمه التجاري والحساب والمبلغ وعدد الحركات.

التأكيد لا يقبل مبلغاً فعلياً مختلفاً عن المتوقع. لذلك السطور المؤكدة هي المبالغ المستلمة المطابقة؛ لا تتوقع حقلاً مستقلاً لفرق تم شطبه أو فعلي مختلف في المحضر. لا تضف «توقيعاً رقمياً موثقاً»؛ المتاح هو اعتماد إلكتروني بهوية المستخدم والوقت.

السجلات القديمة التي ليس لها documentNumber تعرض عبارة واضحة مثل «محضر سابق بدون رقم مستند»، ولا تعرض GUID بديلاً. أسماء الاعتماد الجديدة لا تتغير بتغيير اسم حساب المستخدم لاحقاً. الأسماء القديمة الناقصة يمكن استكمالها للعرض من Identity عند توفرها، بدون إعادة كتابة التاريخ المالي.

## 4. أرصدة الحسابات الفرعية — `subaccounts`

يعتمد على `accounts`. يعرض شجرة الحسابات وحسابات الترحيل مع أول المدة والوارد والصادر والتحويلات وآخر المدة. لا يعيد قائمة تفاصيل `movements` لهذا النوع.

استعمل `parentId` لبناء العرض، و`isPosting` للفصل بين حساب حقيقي وصف تجميعي. لا تجمع صف الأب ثم صفوف الأبناء في الإجمالي النهائي. عند تصفية الشركة، قد تبقى عناوين تجميعية حتى لو كانت بعض الحسابات بلا حركة. لا تحذف حساباً له أول مدة لمجرد أن حركة الفترة صفر.

التقرير ليس ميزان مراجعة للأستاذ العام ولا حساب أرباح وخسائر. سمِّ الأعمدة «مقبوضات/مدفوعات/تحويلات» وفق العقد، ولا تفترض مدين/دائن محاسبيين لكل نشاط خارج نطاق الخزينة.

## 5. كشف التجارية — `trading`

يعرض أقسام الحسابات والحركات على غرار movements، لكن الخادم يثبت كفيل مؤسسة التجارية الحالية ذات المعرف التجاري `7038745530`. لا تطلب من المستخدم اختيار كفيل آخر داخل هذا التقرير، ولا تربطه بالهوية غير المعينة `7007559092`.

اعرض رسوم التجارية وتصفياتها وحسابها المركزي والبنك ومقاصة بترو آب والتحويلات والقيود اليدوية ذات الصلة. `businessPurpose` يميز غرض حركة جاهز إذا توفر، و`posting.kind` يميز طبيعة قيد الخزينة. لا تستنتج أن كل رصيد التجارية صافي ربح أو أن كل تحويل قبض جديد.

## 6. مطابقة بترو آب — `petroapp`

يعتمد على `fuel`، مع صف لكل كفيل. لا تعرض جدول تفاصيل movements لهذا النوع. الخادم قد يرجع `accounts` أيضاً؛ إذا عرضتها فسمها أرصدة مقاصة خزينة، لا أرصدة محفظة. الفلاتر الأساسية للمطابقة: التاريخ والكفيل. لا تعرض فلتر الحساب/الغرض كأنه يرشح أدلة التمويل والبيان والاستهلاك؛ هذه الأدلة على مستوى الكفيل.

| الحقل | عنوان العرض | المعنى |
|---|---|---|
| `collections` | تحصيل جاهز بمقاصة بترو آب | صافي القيود الموقعة بموقع بترو آب في النطاق |
| `funding` | التمويل المثبت | مجموع أدلة Funding السارية في النطاق، أوnull |
| `allocatedCollections` | التحصيل المخصص | مجموع تخصيص الأدلة السارية، أوnull |
| `unallocatedCollections` | غير المخصص | collections − allocatedCollections |
| `fundingDifference` | فرق التخصيص عن التمويل | allocatedCollections − funding |
| `openingStatement` | رصيد البيان الافتتاحي | رصيد نهاية اليوم السابق لأول يوم بالضبط |
| `closingStatement` | رصيد البيان الختامي | رصيد نهاية آخر يوم بالضبط |
| `importedConsumption` | الاستهلاك المستورد | استهلاك الوقود المتاح بشروط اكتمال الفترة |
| `status` | حالة المطابقة | Matched / Difference / Unverified |

معاني الحالة:

| القيمة | النص العربي | العرض |
|---|---|---|
| Matched | متطابق | الأدلة المطلوبة متاحة والمعادلات متطابقة |
| Difference | يوجد فرق | الأدلة المطلوبة مكتملة لكن هناك فرق في معادلة أو تخصيص |
| Unverified | غير متحقق | بعض الأدلة أو الاستهلاك المطلوب غير متوفر؛ لا تعلن المطابقة |

شرط المطابقة الحالية يشمل:

```text
التحصيل = التخصيص
التخصيص = التمويل المثبت
رصيد البداية + التمويل المثبت - الاستهلاك = رصيد النهاية
```

حتى لو كان فرق تخصيص ظاهر غير صفر مع نقص بيان آخر، قد تبقى الحالة Unverified. اعرض الأرقام المتاحة ورسالة نقص الأدلة، ولا تغير حالة الخادم إلى «متطابق» محلياً.

كل null يعني «غير متحقق/الدليل غير متاح»، وليس صفرًا. الدليل المسجل فعلاً بصفر قيمة معروفة ويمكن عرضه 0.00. لا تستخدم `value || 0` أو `value ?? 0` في عرض المطابقة.

الاستهلاك الموجود في النظام شهري. يعرض فقط عندما يبدأ النطاق أول شهر وينتهي آخر شهر، وتتوفر استيرادات مكتملة لكل الأشهر المطلوبة ولا يوجد دليل تدقيق يثير تغير ملكية بطاقة الوقود المستخدم في الحساب. خلاف ذلك يرجع null. لا تقسم إجمالي الشهر على عدد الأيام لصنع استهلاك يومي. استيراد الوقود نفسه يتبع نظام الوقود الموجود، وليس API جديداً في حزمة الخزينة.

للمقارنة مع بيان البداية يجب تسجيل رصيد بتاريخ اليوم السابق تحديداً؛ لا يستخدم التقرير آخر رصيد أقدم بشكل تقريبي. الأدلة البديلة تستبعد الأصل من الحساب المالي، مع بقاء الأصل في سجل الأدلة.

## 7. تنزيل Excel وPDF

الصلاحيتان مطلوبتان: `jahez.financial-reports.read` و`jahez.financial-reports.export`. لا تستخدم خدمة التصدير العامة أو تصدير جدول الصفحة محلياً لهذا الغرض.

```http
GET /api/jahez/v3/treasury/reports/movements/export?format=pdf&fromDate=2026-10-01&toDate=2026-10-19
```

| الصيغة | Content-Type |
|---|---|
| xlsx | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` |
| pdf | `application/pdf` |

استعمل blob ورأس `Content-Disposition` إذا كان متاحاً عبر إعداد CORS في الاستضافة. إذا تعذر قراءة الرأس استخدم اسماً وصفياً من نوع التقرير والتاريخ والصيغة، وليس معرف المستخدم أو المندوب. الخادم ينتج اسماً مثل `jahez-movements-20261001-20261019.pdf`.

```ts
const { blob } = await treasury.exportReport('movements', 'pdf', filter);
const url = URL.createObjectURL(blob);
const link = document.createElement('a');
link.href = url;
link.download = `jahez-movements-${filter.fromDate}-${filter.toDate}.pdf`;
document.body.appendChild(link);
link.click();
link.remove();
// Revoke when the download/preview no longer needs the URL.
setTimeout(() => URL.revokeObjectURL(url), 1000);
```

مثال المتصفح السابق لا يطبق في Server Component. عميل الطلبات يأخذ التوكن من دورة المصادقة الموجودة؛ لا تضع توكناً ثابتاً في الكود أو عنوان التنزيل. يمكن فتح PDF في معاينة blob إذا كانت سياسة المتصفح تسمح، مع الاحتفاظ بزر تنزيل.

التنزيل كامل النطاق المطابق ولا يتوقف عند page/pageSize. الحد المتزامن 10,000 قيد تفصيلي؛ عند تجاوزه يرجع 400 برسالة تضييق الفلاتر، وليس ملفاً جزئياً أو رابط مهمة خلفية. بعض التقارير لا تعرض تفاصيل القيود، لكن فحص حد القيود للنطاق يطبق عليها أيضاً باستثناء المحضر الذي يبنى من نسخته المجمدة. إذا لم توجد بيانات، قد يحتوي PDF/Excel صفوف الأرصدة أو رسالة عدم وجود بيانات؛ لا تعتبر الاستجابة الفارغة فشلاً.

اعرض «جاري تجهيز الملف» وامنع طلباً مكرراً أثناء التجهيز. عند خطأ HTTP اقرأ ProblemDetails أولاً ولا تحفظ ملف JSON باسم pdf. API والملفات تشترك في الحسابات والفلاتر؛ لا تعيد حساب مجاميع أخرى داخل الواجهة.

## 8. سياسة الأسماء والطباعة

PDF عربي RTL وExcel باتجاه RTL صادران من الباك إند. يظهر اسم الشخص لا GUID، ويحذف عمود معرف دفعة التحويل الداخلي من الطباعة. اسم الحساب بدلاً من معرفه، والكفيل من الملكية المثبتة. يمنع renderer طباعة GUID مضمّن في نص قديم أيضاً.

اعرض الأسماء المحفوظة وقت الإجراء إذا كانت موجودة. لا تستبدل اسم محاسب قديم باسم جديد من دليل المستخدمين بعد تغيير الاسم. عند فقد الاسم استخدم العبارة البديلة الموضحة في [الفهرس](README.md). لا توهم أن كل تحويل له مندوب؛ الحركات المركزية قد لا تتعلق بمندوب.

في شاشة الدفتر قد تبقى روابط التفاصيل الداخلية ضرورية، لكن التسمية تكون «عرض العملية» أو«عرض المحضر»، لا نص المعرف. لا تستخدم أسماء الأشخاص كمعرفات API؛ تشابه الأسماء ممكن، والربط الداخلي يظل بالمعرف دون عرضه.
